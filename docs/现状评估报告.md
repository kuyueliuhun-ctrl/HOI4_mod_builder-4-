# HOI4 Mod 编辑器现状评估报告（v0.6.1，2026-08-31）

> 评估方式：只读代码审查 + 真实基准实测 + 契约/测试盘点。基线：815 条契约用例全绿，
> 代码规模 `src/` 258 个模块 / 约 71k 行，`tests/` 117 个文件。
> 证据格式均为 `文件:行号`，可直接定位。

## 0. 总评

| 维度 | 评分 | 一句话结论 | 最高风险 |
| --- | --- | --- | --- |
| 文件安全性 | 4 / 5 | 原子写+路径安全+写入纪律三层防线成型，允许直写的豁免全部是程序配置类 | 权限回退 chmod 0o666、撤销快照内存无上限 |
| 算法复杂度 | 2.5 / 5 | 单点致命：核心解析器行号统计为 O(n²)，实测双倍输入≈4 倍耗时 | 1MB 级脚本文件解析≈36s |
| 性能 | 3 / 5 | 地图/加载层缓存与向量化做得好，但被解析层 O(n²) 拖累；UI 全同步 | 打开大文件阻塞主线程 |
| 游戏文件全量读取 | 3.5 / 5 | 100 类内容类型 + raw 兜底覆盖广，但保真有硬伤（注释/CRLF 丢失） | 通用树保存整文件重序列化丢注释 |
| UI 贴合度 | 3.5 / 5 | 工作台+专用编辑器+树编辑器兜底的工作流贴合，但保存缺预览/并发保护 | 无 diff 预览、无外部修改检测 |

综合 ≈ **3.3 / 5**：功能广度与工程纪律是强项；解析性能与「保存不破坏原格式」是两大短板。

### 1.1 做得好的

- ✅ 原子写+编码契约+撤销快照三合一：写前校验 BOM/可编码性，mkstemp 临时文件 +

  「写入失败不破坏原文件」有契约测试（`tests/test_contracts.py:109`）。
- ✅ 写入纪律有可执行扫描器：AST 级识别 `open(w/a/x)`/`write_text`/`write_bytes`/

  全项目 179 个模块共 283 处写入走 `atomic_write_text`，仅 settings.json 等程序数据
  直写且全部登记在 allowlist（`tools/write_discipline_allowlist.json:3-45`）。
- ✅ mod 收敛策略明确：原版文件编辑前自动复制进 mod（`src/state_build_ops.py:29-56`），
  地图归属写回只写 mod、游戏本体拒绝（`src/state_edit_ops.py:1-11,125-158`）。

### 1.2 风险与建议

| 级别 | 问题 | 证据 | 影响 | 建议 |
| --- | --- | --- | --- | --- |
| Medium | PermissionError 回退时把目标文件 chmod 0o666 后不再恢复 | `src/write_utils.py:88-94,127-132` | Windows 上把只读文件改为可写，Linux 上变成全员可写，弱化权限且不可逆 | 记录原 mode，replace 成功后恢复；失败再降级只读 |

| Low | 写入纪律豁免是模块级：同一模块未来新增的 mod 内容直写也会被静默放行 | `tools/check_write_discipline.py:84`（`module_allowed` 整文件豁免） | allowlist 随时间腐化 | 豁免尽量降为行级；模块级豁免在 allowlist 中加 `content_kind` 断言（只允许 settings/json） |
| Info | `undo` 恢复成功才弹栈、失败保留条目，语义正确 | `src/undo_mgr.py:41-59` | 无 | 保持 |

## 2. 算法复杂度（P0 结论：解析器是 O(n²)）

### 2.1 实测基准（真实运行，非推测）

合成数据（每行一个 focus 块，约 120B/行）跑 `parse_pdx_script`：

| 输入规模 | 字符数 | 耗时 | 倍增比 |
| --- | --- | --- | --- |
| 1,000 行 | 119 KB | 0.56 s | — |
| 2,000 行 | 241 KB | 2.23 s | ×4.0 |
| 4,000 行 | 485 KB | 8.95 s | ×4.0 |
| 8,000 行 | 976 KB | 36.26 s | ×4.05 |

输入翻倍耗时×4，即 **O(n²)**。同规模下把行号统计改为一次线性扫描的原型
（增量 `count`，逻辑等价）：

| 输入规模 | 原型 tokenize 耗时 |
| --- | --- |
| 8,000 行 | 0.076 s（对比全解析 36s，瓶颈几乎全在行号统计） |

### 2.2 根因与同类热点

| 级别 | 位置 | 证据 | 复杂度 |
| --- | --- | --- | --- |
| P0 | `pdx_parser` 每个 token 用 `text[:m.start()].count('\n')` 求行号 | `src/pdx_parser.py:63-66` | 每 token O(n) → 全文件 O(n²) |
| P0 | `tree_node._tokenize` 同样的每-token 行号回数 | `src/tree_node.py:612-614` | O(n²)，`parse_pdx_text_to_nodes` 是 state/bop/oob 等所有 loader 的公共入口 |
| P0 | `focus_parser` 行号多处 `content[:pos].count('\n')` | `src/focus_parser.py:69,76,125,139,193-197` | O(n·m)，按字段解析再乘一层 |
| P1 | 块定位器每次调用重新全文件分词：`icon_ops.find_block_range`、`focus_algo.find_focus_block_range` | `src/icon_ops.py:22-25`、`src/focus_algo.py:76-78` | 单次 O(n)；画廊按实体循环调用时 O(n·m) |
| P1 | `entity_scanner` 子块筛选线性扫描全 spans：character 提取每个 span 扫一遍全部 spans | `src/entity_scanner.py:78-84` | O(m²)（m=块数），大角色文件变慢 |
| P1 | `_apply_locate_rule` keys 分支嵌套去重用 `any()` 逐对比较 | `src/entity_scanner.py:541-547` | O(k²)；wrap 分支对每个包装块扫全 spans（`src/entity_scanner.py:549-557`） |
| Info | 文档自证：完整 `parse_pdx_script` 过慢，60 个国策文件需数十秒，为此专门做了 `_quick_focus_scan` 绕行 | `src/entity_scanner.py:135-144` | 与基准一致 |

### 2.3 做得好的（保持）

- ✅ 地图层全面向量化：provinces.bmp 一次 LUT 映射为 id 矩阵（`src/map_loader.py:90-113`），
  中心点用 bincount 批量计算并缓存（`src/map_loader.py:142-161`），
  国家着色/边界 overlay 一次合成并缓存、归属编辑后显式失效
  （`src/map_loader.py:316-318,320-431`）。
- ✅ 加载层有缓存：BOP 定义缓存（`src/bop_loader.py:26-31,119-151`），
  通用/原始块 loader 共享 `ai_loader._AI_CACHE`
  （`src/generic_block_loaders.py:58-65`、`src/raw_block_loaders.py:46-53`）。
- ✅ 块扫描主体是单遍 O(n)：`_scan_blocks` + 单调栈 `_block_spans`
  （`src/entity_scanner.py:265-309`）。

### 2.4 测试覆盖缺口

无任何「性能/复杂度」契约：建议加一条基准契约——同一输入翻倍，解析耗时比 ≤ 2.5x，
防止 O(n²) 回归；并给 `_quick_focus_scan` 与完整解析结果一致性加抽样对拍测试。

## 3. 性能

1. **解析是当前最大瓶颈**（见 §2 基准）：state/bop/oob/ideologies 等所有走
   `parse_pdx_text_to_nodes` 的加载在整库加载时都被放大
   （如 `src/state_loader.py:113-133` 全量重载）。
2. **UI 主线程全同步**：文件打开→解析→建树→渲染都在主线程（`src/main_window_docks.py:518-558`）；
   已有 quick-scan 缓解国策/科技画布，但通用树与 raw 编辑器仍会卡顿大文件。
   建议：>256KB 的文件解析放 `QThread`/`QThreadPool` + 进度提示。
3. **内存**：树编辑器撤销栈 200 份整树深拷贝（`src/generic_tree_editor.py:209-211`）
   叠加全局 50 文件字节快照（`src/undo_mgr.py:14-36`），大文件场景内存峰值高。
4. **缓存失效粒度粗**：raw 编辑器每次 `_reload` 清空整个 `_AI_CACHE`
   （`src/raw_block_editor.py:94-99`），一处保存导致全部类型重扫；建议按 (kind,path) 精确失效。
5. 设计器「同款同步」逐国家整文件读+改+写（`src/designer_base.py:675-713`），
   数十个国家时可接受，上百国家建议批量+进度。

## 4. 游戏文件全量读取

### 4.1 覆盖广度（强项）

- ✅ 内容类型注册表 100 项，覆盖 `common/` 全部主要子目录、`events/`、
  `history/`（states/countries/units/general）、`interface/`、`map/`（terrain/strategicregions/
  supplyareas）、`localisation/`、`gfx/`、`.mod`，并留 `generic` 兜底
  （`src/content_types.py:27-142`）。
- ✅ 图标/头像提取规则 9 类，含嵌套路径（`src/content_types.py:163-298`）。
- ✅ 未知/未建模内容有三层兜底：focus 的 unknown 字段保留（`src/focus_parser.py:255-265`）；
  通用块 loader 保留 `raw`（`src/generic_block_loaders.py:75-85`）；
  RawBlockEditor 按块原文替换、块外内容不动（`src/raw_block_loaders.py:59-71`、
  `src/raw_block_editor.py:158-178`）。
- ✅ 二进制资源只读可视化：provinces/heightmap 经 numpy/PIL 读入（`src/map_loader.py:90-113,219-235`），
  `definition.csv` 解析（`src/map_loader.py:60-88`）；dds 有独立工具链（`src/dds_loader.py`/`src/dds_convert.py`）。

### 4.2 保真度硬伤（弱项）

| 级别 | 问题 | 证据 |
| --- | --- | --- |
| High | 两个解析器都在解析阶段丢弃注释；通用树保存整文件重序列化 → **保存一次，全文件注释消失** | `src/pdx_parser.py:8-37`、`src/tree_node.py:573-592`（strip 后才分词）；保存路径 `src/generic_tree_editor.py:1111-1164` |
| High | 保存把 `splitlines()` 结果用 `\n` join → 全文件 CRLF 被改成 LF；原缩进风格只在「块级 raw_lines」场景保留 | `src/generic_tree_editor.py:1153-1164`；对比仅国策字段级保留 `src/tree_node.py:137-249` |
| Medium | `parse_pdx_script` 把比较语句折叠成字符串塞进 `'list'`（触发条件无结构、无法无损往返）；`tree_node` 侧倒是保留了 raw_lines 语句节点 | `src/pdx_parser.py:112-124` vs `src/tree_node.py:556-565` |
| Medium | 本地化只读 `simp_chinese`，多语言 mod 的其他 `l_english` 等完全不可见 | `src/localization_mgr.py:98-120` |
| Low | 国家 tag 识别靠文件名/内容启发式，非常规命名会漏 | `src/entity_scanner.py:377-442` |
| Low | 重复 ID 检查排除 state/country_history/generic/gui | `src/game_data.py:240-248` |

### 4.3 结论

「全量读取」= **广度达标（约 100 类 + generic 兜底 + raw 逃生门），深度不足**：
读进来都行，但经通用树「读→写」一圈后注释/CRLF 会被改写——对「只看不改」无影响，
对「改一处、存全文」是隐性破坏。BOM/日期/中文键引号规则处理正确
（`src/tree_node.py:5-19,103-111`），本地化 yml 的 BOM 保留正确
（`src/translation_editor.py:221-230`）。

## 6. 优先级建议

**P0（当前就应做）**
1. 解析器线性化：`pdx_parser.py` / `tree_node.py` / `focus_parser.py` 行号统计改增量扫描
   （原型已验证 36s → 亚秒级）；加「翻倍输入耗时比 ≤ 2.5x」基准契约防回归。
2. 通用树保存保真：未改动节点全量保留 `raw_lines`（含注释/空行），或保存前弹 diff 预览；
   同步加 mtime 外部修改检测与 round-trip 契约（含注释+CRLF 字节级一致用例）。

**P1**
3. `write_utils` chmod 回退后恢复原权限；`undo_mgr` 加字节预算；
   读取侧 `errors="ignore"` 改严格并上报。

   复用 `_scan_blocks` 缓存。
5. >256KB 文件的解析/保存移后台线程 + 进度条；`_AI_CACHE` 按 (kind,path) 精确失效。

**P2**
6. 本地化多语言读取/编辑（至少 l_english 只读展示）。
