# 启动器（launcher.py）说明

> 本文件是“换电脑也能直接启动”的保障：项目根、虚拟环境、Python 解释器全部由
> 启动器自动解析，不再依赖任何写死的绝对路径。

## 为什么需要启动器

旧启动脚本存在三类“换个电脑就失败”的路径问题：

1. **虚拟环境路径写死**：`启动.sh` 曾硬编码 `/root/hoi4_builder_venv`，换电脑/
   换用户后必然找不到。
2. **运行目录依赖**：直接 `python src/main.py` 时，若当前目录不是项目根，
   `settings.json`、`templates/` 等相对路径会失效。
3. **Windows/WSL 共用仓库时的 `.venv` 冲突**：Windows 的 `.venv` 是
   `Scripts/python.exe`，Linux/WSL 需要 `bin/python`，混用会互相破坏。

启动器把这些问题全部收敛到单一入口 `launcher.py`。

## 使用方法

### 日常启动

```bat
:: Windows
启动.bat
```

```bash
# Linux / WSL
bash 启动.sh
```

首次运行若没有可用虚拟环境，启动器会自动：

1. 探测本机 Python 3.10+（优先 3.14）；
2. 在项目内创建虚拟环境（Windows 用 `.venv`，WSL/Linux 自动避开 Windows `.venv`
   改用 `.venv-linux`）；
3. 安装当前平台依赖（`requirements.txt` / `requirements-wsl.txt`）；
4. 自动补充 PyQt6 的 Qt DLL/插件路径（`PATH` 与
   `QT_QPA_PLATFORM_PLUGIN_PATH`），降低“找不到 Qt 平台插件”的路径类故障；
5. 最后以项目根为工作目录启动 `src/main.py`。

### 首次安装 / 重新安装依赖

```bat
setup.bat
```

```bash
bash setup.sh
```

等价于 `启动器 --setup --verify`：准备环境后运行全量契约验证。

### 便携模式（无需预装 Python）

如果项目目录内存在 `portable\python\python.exe`（Windows）或
`portable\python\bin\python`（Linux/WSL），启动器会自动进入便携模式：
直接使用随包 Python，不再要求系统预装 Python，也不再创建 venv。

```bat
:: Windows 便携版
启动.bat
```

便携版打包方法见 `docs/便携版打包.md`。

### 高级用法

```bash
# 只准备环境，不启动
python3 launcher.py --setup

# 准备环境后跑全量验证
python3 launcher.py --verify

# 只检查，不创建、不安装、不启动（适合 CI）
python3 launcher.py --check

# 指定虚拟环境目录（相对路径按项目根解释）
python3 launcher.py --venv /custom/path/venv

# 向主程序透传额外参数
python3 launcher.py -- --some-app-arg
```

## 路径规则

| 项 | 规则 |
| --- | --- |
| 项目根 | 始终取 `launcher.py` 所在目录的绝对路径，与调用者当前目录无关 |
| 工作目录 | 启动主程序时固定为项目根 |
| Windows 虚拟环境 | 项目内 `.venv`；若 `.venv` 是 Linux 环境，自动改用 `.venv-win` |
| WSL/Linux 虚拟环境 | 已有 Linux `.venv` 则复用；否则若 `.venv` 是 Windows 环境，自动用 `.venv-linux` |
| 自定义虚拟环境 | `--venv` 覆盖；也可设置环境变量 `HOI4_VENV`（当前版本以 `--venv` 优先） |
| 依赖文件 | Windows 用 `requirements.txt`；Linux/WSL 用 `requirements-wsl.txt` |

## 常见问题

- **提示找不到 Python 3.10+**：先安装 Python 3.14（或 3.10+），再运行 `启动.bat` /
  `bash 启动.sh`；或者使用 `docs/便携版打包.md` 生成的便携版，完全不用装 Python。
- **提示虚拟环境目录已存在但不是当前平台可用环境**：一般是 Windows 的 `.venv`
  被 WSL/Linux 启动器碰到；默认会自动改选 `.venv-linux`。若手动指定了冲突目录，
  请删除或换一个目录。
- **首次安装很慢**：需要下载 PyQt6/numpy/Pillow/mcp 等依赖，属正常现象。
- **Windows 下手动设 `QT_QPA_PLATFORM=offscreen` 报“找不到平台插件”**：
  不要写 `set QT_QPA_PLATFORM=offscreen && ...`（尾部空格会进入变量），应写
  `set QT_QPA_PLATFORM=offscreen& ...` 或 `set "QT_QPA_PLATFORM=offscreen"`。
- **想用项目现有的 Linux 虚拟环境**：`bash 启动.sh --venv /root/hoi4_builder_venv`。
