## 1. 总体规律

### 高分 UI（8~9 分）共同特质

| 特质 | 说明 |
|---|---|
| **完整读写闭环** | 用户能在界面内完成“浏览→编辑→保存”全流程，不需要跳转到其他编辑器 |
| **本地化深度集成** | 虚拟翻译节点（A3）、右键快速本地化（A2/B1）、名称键+中文双列展示 |
| **四层分离清晰** | 算法/绘图/UI/信号槽职责分明，代码可维护（B1 从 2476→1188 行） |
| **游戏内体验还原** | B1 国策树“像游戏内一样”绘制，A1 双模式（经典/工作台）适配不同场景 |
| **安全写入** | 原子写 + 撤销快照 + 原版自动落 mod，用户不怕改坏 |
| **信息密度合理** | 固定宽度面板（330px）、分组折叠、搜索过滤，不浪费空间 |

### 低分 UI（2~6 分）共同缺陷

| 缺陷 | 涉及 UI |
|---|---|
| **只读不写/编辑断裂** | C7（无法增删决议）、C8（desc 键缺失/无法关联） |
| **本地化缺失** | C2/C3/C4（模块名/槽位名未翻译）、C8（肖像/描述未展示中文） |
| **关键数据字段遗漏** | C1（地形仅 movement，缺 attack/defense）、C8（肖像只存 texture key 不渲染图片） |
| **用户无法选择核心对象** | C2/C3/C4（无法选择船体/机体/底盘，只能编辑已有变体） |
| **布局/视觉问题** | C2/C3/C4（文字与槽位间隔大、不对称、锁定逻辑不直观） |
| **初始视野不友好** | C6（未定位到所选国家） |

## 2. 逐项评估

### A1 主窗口（9分）

**优点**
- 架构清晰：设置持久化（settings.json 逐键防御读取）、双 UI 模式（classic/workbench）、工具菜单委托 `menu_factory` 构建
- 功能覆盖全：25+ 工具入口、文件树/工作台/画布装配、反馈工具栏
- 写入安全：所有 mod 文件走原子写 + 撤销

**缺点**
- `MyWindow` 仍有 1547 行，承担初始化/路由/设置过多职责
- 工具菜单项无分类（25 项平铺），新用户认知负担高

**缺失/可改进**
- 工具菜单可加二级分类（地图类/设计器类/数据类/本地化类）
- 最近打开的 mod 列表（MRU）缺失

**用户备注回应**
- 9 分合理，无明显功能/设计抱怨。

### A2 工作台（8分）

**优点**
- 信号解耦（8 个 pyqtSignal），类型列表分组（专门类型置顶 + 分隔线 + 通用类型）
- 纯选择与写操作分离（“选择国家”不写文件，“国家设置”显式写操作 + tooltip 提示）
- 搜索实时过滤、双模式（文件/无文件）

**缺点**
- 无文件模式国家栏在内容区下方，首次使用不易发现
- 实体列表无图标预览（仅文字）

**缺失/可改进**
- 实体列表项可加小图标（决议/事件/理念各有 GFX）
- 文件列表可显示 mod/game 来源标记

**用户备注回应**
- 8 分合理，扣分可能在信息密度和视觉引导。

### A3 通用 PDX 树形编辑器（8分）

**优点**
- 虚拟翻译节点（“翻译”/“文本描述”注入树模型，inline 编辑）
- 块级保存（`block_range` 只重写编辑区域，保留原格式）

**缺点**
- 树视图无语法高亮（纯黑白文本）
- 大文件（>5000 行）性能未优化

**缺失/可改进**
- 可加 PDX 语法高亮（key/value/block 着色）
- 可加“定位到行”功能（从错误日志跳转）

**用户备注回应**
- 8 分合理，作为兜底编辑器已够用。

### B1 国策树画布（9分）

**优点**
- 游戏内视觉风格高度还原，节点卡片/连线/图标布局符合玩家直觉
- 四层拆分彻底（focus_algo/render/ctrl/view），架构清晰可维护
- 文件/无文件双模式完整支持，适应不同工作流
- 图标上传流程顺畅，gfx sprite 自动注册

**缺点**
- 国策属性编辑分散在节点弹窗，缺少批量编辑/全局视图
- 国策间依赖关系（prerequisite）可视化不够直观，复杂树交叉连线易混乱
- 布局算法对超大树（100+ 国策）性能未优化，拖拽偶有卡顿
- 国策与事件/决议/理念的引用联动检测较弱

**缺失/可改进**
- 国策树导入/导出（JSON/图片）
- 自动布局优化（减少交叉、支持手动微调锁定）
- 国策完成条件/效果的可视化预览
- 与工作台其他类型的双向跳转（点国策→编辑关联事件）
- 国策树版本对比（diff 视图）

**用户备注回应**
无

### B2 科技树画布（4分）

**优点**
- 与国策树共用画布架构，folder 分组 + path 连线 + BFS 树形布局，复用度高
- 科技树作为独立视图（tech_view.py）已从 focus_view 拆出，符合四层分离规范

**缺点**
- 连线混乱说明 path 解析或布局算法对多 parent / 交叉引用的处理不足
- 实体间距过小是布局参数（节点尺寸、行列间距）未针对科技树密度调优
- 大图标（装备迭代）与小图标（加成）视觉区分弱，缺少尺寸/形状/背景色等差异化渲染

**缺失/可改进**
- 布局算法需增加科技节点密度自适应（增大间距、支持缩放适配）
- 连线算法需处理交叉（正交路由或分层避让）
- 节点渲染应按科技类别（装备/加成/学说）区分图标尺寸与卡片样式
- 缺少科技前置关系的视觉层级（如颜色编码或线型区分）

**用户备注回应**
- 连线混乱 → 需重构 path 连线路由（建议正交折线 + 交叉检测）
- 间隔太小 → 调整 BFS 布局的 level_gap / sibling_gap 参数或引入自适应
- 大小图标区分 → 在 focus_render 的节点卡片渲染中按科技 type 分支处理（装备类用大图标卡，加成类用小徽章）

### C1 师编制编辑器 v2（6分）

**优点**
- 仿游戏内 Division Designer 结构完整（顶部下拉/编制网格/数据面板/地形矩阵）
- 基础数据 12 行 + 战斗数据 8 行 + 装备花费 + 地形适应性 8 徽章卡片，信息密度高
- 右侧面板固定 330px 不影响布局

**缺点**
- 地形矩阵仅展示移动加成一项，信息不完整
- 地形对战斗的影响（攻击/防御修正）是关键评估维度，缺失导致用户无法判断编制在特定地形的真实战斗力

**缺失/可改进**
- 地形徽章卡片应扩展为三列（移动/攻击/防御），或改为三行 tab 切换
- 可增加“综合地形评分”汇总（加权平均）
- 地形数据在 oob_loader 的 terrain{} 块中已解析 movement，需补全 attack/defense 字段的解析

**用户备注回应**
- 地形加成三项（移动/攻击/防御）→ 需扩展 oob_loader 解析 terrain 块的 attack/defense 子键（若游戏文件支持），UI 徽章卡片改为三列布局或增加子标签页

### C2 舰艇设计器（5分）

**优点**
- 槽位网格 + 属性估算 + 跨国家同步 + 模板保存，功能链路完整
- 原版自动落 mod 的写入安全机制已实现
- 模块按 allowed categories 过滤正确

**缺点**
- 本地化不完全（模块/船体名显示英文键）
- 界面布局不对称，文字与槽位间距过大影响信息密度
- 部分槽位锁定逻辑用户无法理解（缺少 tooltip 解释）
- 船体无法在 UI 上切换选择（只能看当前设计的船体）

**缺失/可改进**
- 本地化接入 loc_manager（模块名/船体名/类别名）
- 槽位布局改为文字在槽位下方、删除多余间隔，提升紧凑度与对称性
- 锁定槽位增加 tooltip 说明“该槽位由船体固定，不可更换”
- 增加船体选择下拉（列出同 archetype 的可切换船体）

**用户备注回应**
- 文字放槽位下 + 删间隔 → 调整 QGridLayout 布局，label 放按钮下方、margin 设为 0
- 锁定槽位 → 增加 tooltip 解释锁定原因
- 船体选择 → 顶部增加 QComboBox 列出可切换船体（同 archetype 变体）

### C7 力量平衡工作台（4分）

**优点**

### C8 角色编辑器（4分）

**优点**
- 单页三栏结构清晰（角色列表/基本信息+描述+肖像槽位/职责表单）
- roles 结构化解析已实现
- 只替换 name/portraits 区保留 roles 的写入策略安全

**缺点**
- 未展示角色肖像（portraits 路径已解析但未渲染图片）
- 未展示角色本地化（name/desc 显示键而非翻译）
- 角色工作台无法正确调用（路由或实体提取有 bug）
- 图片上传应学国策（走 icon_ops 流程）
- 所有角色均无 desc 键（解析或游戏文件本身无 desc，需核实）

**缺失/可改进**
- 肖像槽位渲染实际图片（DDS→PNG，复用 dds_loader）
- 本地化接入（name/desc 查 l_yml）
- 修复工作台调用路由（核实 workbench 的 character 实体提取与双击分发）
- 图片上传走 icon_ops.write_file_utf8 + gfx sprite 注册
- desc 键需核实游戏文件是否支持（若不支持则 UI 不展示该字段）

**用户备注回应**
- 肖像展示 → portraits 块已解析，用 dds_loader 加载并渲染到槽位
- 本地化 → 接入 loc_manager.get_name
- 工作台调用 → 排查 entity_scanner 的 character 提取与 app_routes 分发
- 图片上传 → 复用 icon_ops 流程
- desc 键 → 检查游戏文件 character 定义是否含 desc，若无则 UI 移除该字段

## 3. 修复优先级建议

| 优先级 | 项目 | 影响 |
|--------|------|------|
| **P0** | C3/C4 槽位解析/布局 bug + 机体/底盘选择 | 设计器核心功能不可用，2 分评价，影响所有装备设计工作流 |
| **P0** | C8 角色工作台调用路由修复 | 工作台无法正确调用 = 功能入口断裂，用户完全无法使用 |
| **P1** | C3/C4 本地化全量接入 | 界面显示英文键，用户体验差，但与舰艇共用 designer_common，修复可复用 |
| **P1** | C8 肖像渲染 + 本地化 | 角色编辑器核心展示缺失，portraits 数据已有但未渲染 |
| **P1** | B2 科技树连线混乱 + 间距过小 | 科技树是高频使用功能，连线混乱直接影响可用性 |
| **P1** | C6 OOB 默认视野定位到所选国家 | 7 分基础上的关键体验缺陷，每次打开需手动找国家 |
| **P2** | C1 地形矩阵扩展（攻击/防御） | 信息不完整但不影响编制编辑主流程 |
| **P2** | C2 舰艇布局优化 + 船体选择 + 锁定 tooltip | 5 分基础上的体验优化 |
| **P2** | C7 BOP 动作 CRUD + 内联编辑 | 从展示升级为可编辑，但当前可通过树编辑器兜底 |
