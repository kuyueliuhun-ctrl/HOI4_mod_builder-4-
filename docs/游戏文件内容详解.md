## 一、前置知识：PDX 脚本语言

HOI4 的绝大部分数据文件使用 Paradox 自研的 **Clausewitz 脚本语言**，语法类似 JSON / XML 的混合体。

### 1.1 基本元素

| 元素 | 写法 | 说明 |
|------|------|------|
| 键值对 | `key = value` | 最基本单元，值可以是数字、布尔（yes/no）、标识符或字符串 |
| 代码块 | `key = { ... }` | 花括号包裹的子作用域 |
| 字符串 | `"带空格的文本"` | 必须用英文双引号；无空格的关键字可省略引号 |
| 注释 | `# 这是注释` | `#` 到行尾均为注释 |
| 布尔 | `yes` / `no` | 相当于 true / false |

```text
# 单个国策节点示例
focus = {
    id = GER_rearmament
    icon = GFX_goal_generic_construct_civilian
    cost = 10
    available = { has_political_power > 100 }
    completion_reward = { add_political_power = 120 }
}
```

### 1.2 作用域（Scope）

脚本是**作用域嵌套**的。上层代码决定了当前作用域（国家 / 州 / 角色 / 部队等），子块切换作用域。

- **国家作用域（country）**：`add_stability`、`has_war`、`tag = GER`
- **州作用域（state）**：`is_core_of`、`add_building_construction`
- **角色作用域（character）**：`has_trait`、`is_field_marshal`
- **部队作用域（unit）**：`division_has_majority_template`

关键作用域代名词：

| 关键字 | 含义 |
|--------|------|
| `ROOT` | 当前主体（触发此事件/使用此国策树的国家） |
| `FROM` | 触发方（如让另一国触发本事件的国家） |
| `PREV` | 上一层作用域 |
| `THIS` | 当前作用域 |

### 1.3 三大脚本元素

整个游戏脚本体系由三类构成，几乎每个文件都在写这三样东西：

| 元素 | 关键字 | 出现位置 |
|------|--------|----------|
| **触发器 trigger** | 判断真假的条件 | `available` / `visible` / `allowed` / `bypass` / `trigger` / `limit` |
| **效果 effect** | 改变游戏状态的指令 | `completion_reward` / `complete_effect` / `option` / `immediate` |
| **修正 modifier** | 持续性数值加成 | `modifier = { ... }` 块内 |

```text
# 触发器（返回真/假）
has_war = yes
has_stability < 0.5
NOT = { country_exists = SOV }
OR = { has_idea = A  has_idea = B }

# 效果（执行动作）
add_political_power = 100
set_global_flag = my_flag
annex_country = { target = SOV transfer_troops = no }

# 修正（持续加成，放在 modifier = { } 内）
stability_weekly = 0.05
research_speed_factor = 0.1
army_attack_factor = 0.2
```

### 1.4 逻辑控制

```text
# 条件分支
if = {
    limit = { has_war = yes }
    add_stability = 0.1
}
else_if = { limit = { has_war = no }  add_war_support = 0.1 }
else = { add_political_power = 50 }

# 概率效果（权重总和不必为 100）
random_list = {
    70 = { add_political_power = 200 }
    30 = { add_political_power = -100 }
}

# 循环（效果类，从 0 到 24，步进 1）
for_loop_effect = { start = 0  end = 24  add = 1  ... }
```

### 1.5 变量系统

```text
set_variable = { var = my_var  value = 10 }
set_temp_variable = { var = temp  value = 5 }   # 临时变量
add_to_variable = { var = my_var  value = 3 }
subtract_from_variable = { var = my_var  value = 1 }
multiply_variable = { var = my_var  value = 2 }
divide_variable = { var = my_var  value = 2 }
clamp_variable = { var = my_var  min = 0  max = 100 }
check_variable = { my_var > 50 }                 # 触发器比较变量
```

### 1.6 AI 权重（ai_will_do / ai_chance）

决定 AI 选择某个国策、决议或事件选项的倾向：

```text
ai_will_do = {
    factor = 10                        # 基础权重
    modifier = {
        factor = 50                    # 满足条件时的权重
        has_war = yes
    }
}
```

> **注意**：`modifier` 内若放国家作用域条件，一个 `modifier` 只能放一个国家的 tag；多个国家需拆成多个 `modifier` 块，否则无效。

## 二、Mod 工程结构

### 2.1 描述文件

HOI4 的 Mod 需要两个描述文件：

| 文件 | 位置 | 作用 |
|------|------|------|
| `xxx.mod` | 用户 `Documents/Paradox Interactive/Hearts of Iron IV/mod/` | 让启动器识别 Mod，含路径指向 |
| `descriptor.mod` | Mod 内容目录内 | 内容目录自身的描述，打包上传时用 |

`.mod` 文件示例：

```text
name = "My Mod"
path = "mod/my_mod"
tags = { "Alternative History" }
picture = "thumbnail.png"
supported_version = "1.14.*"
```

常见字段：`name`（名称）、`path`（相对 mod 目录的路径）、`tags`（标签）、`picture`（缩略图）、`supported_version`（支持版本）、`remote_file_id`（Steam 工坊 ID）、`replace_path`（整目录替换原版，常用于完全重写国策/地图）。

### 2.2 内容目录结构

Mod 内容目录镜像游戏目录，只放**要覆盖/新增**的文件：

```
my_mod/
├── descriptor.mod
├── common/           # 数据定义（覆盖原版 common/ 下同名文件）
├── events/           # 事件
├── history/          # 开局历史
├── localisation/     # 本地化
├── interface/        # .gfx 精灵定义
├── gfx/              # 图像资源
└── ...
```

> **覆盖规则**：Mod 中与游戏同路径的文件会**覆盖/合并**原版；不同文件名则作为新增内容加载。`replace_path` 可强制整个目录只读 Mod 版本。

## 四、国家与意识形态

### 4.1 国家定义 `common/country_tags/`

**作用**：把国家 tag 映射到具体的国家定义文件。文件名常为 `00_countries.txt` 等。

```text
# common/country_tags/00_countries.txt
GER = "countries/Germany.txt"
SOV = "countries/Soviet.txt"
USA = "countries/United States.txt"
```

**规则**：`TAG = "countries/文件名.txt"`，路径相对于 `common/`。新增国家时，文件名为裸 tag（如 `14K.txt`）。

**化妆标签（cosmetic tag，显示名覆盖）**：动态改名/换显示名不写这里，走游戏本体现行机制：

- 别名表：`common/country_tag_aliases/tag_aliases.txt`，定义 3 字母别名 TAG 按触发器条件映射到原国家（用于换显示名/换兵模），映射用 `original_tag`、`has_country_flag`/`has_focus_tree`/`has_cosmetic_tag` 等触发器：
  ```text
  SPC = {
      original_tag = SPR
      has_country_flag = SPR_anarchist_spain_flag
  }
  ```
- 切换效果：`set_cosmetic_tag = SPC`；检测触发器：`has_cosmetic_tag = SPC`。
- 显示名 = 该别名 TAG 的本地化键（`countries_l_simp_chinese.yml` 里 `SPC: "西班牙"`）。
- 校验：别名 TAG 必须 3 字母且不与现有 tag 冲突；无触发器条件时游戏会检查所有国家（性能昂贵，勿用）。
- 旧式资料（QIUQI/RHoiScribe）里的 `TAG: "cosmetic_name"` 写法在本版本已由 tag_aliases 取代，以游戏本体为准。

### 4.2 国家颜色与属性 `common/countries/`

**作用**：定义国家颜色（地图着色）、图形文化、颜色 ui 等。

```text
# common/countries/Germany.txt
color = { 73 89 108 }
graphical_culture = european_gfx
graphical_culture_2d = european_2d
color_ui = { 73 89 108 }
```

| 字段 | 含义 |
|------|------|
| `color` | 地图上的国家颜色（RGB 0-255） |
| `color_ui` | UI 界面颜色 |
| `graphical_culture` | 3D 兵模文化 |
| `graphical_culture_2d` | 2D 兵牌文化 |

### 4.3 意识形态 `common/ideologies/`

**作用**：定义四种基础意识形态（民主/法西斯/共产/中立）及其子意识形态、规则设定。

```text
ideologies = {
    democratic = {
        color = { 65 70 240 }
        types = {
            conservatism = { color = { 60 60 160 } }
            liberalism = { color = { 60 100 180 } }
        }
        rules = {
            can_create_factions = yes
            can_send_volunteers = yes
            ...
        }
    }
    fascism = { ... }
    communism = { ... }
    neutrality = { ... }
}
```

**关键**：意识形态种类英文固定为 `democratic / fascism / communism / neutrality`；子意识形态（如 `nazism`、`leninism`、`liberalism`）定义在 `types` 内。

## 五、国策与持续国策

### 5.1 国策树 `common/national_focus/`

**作用**：定义国家的国策树（National Focus Tree），是 Mod 制作最核心的文件之一。文件位置 `common/national_focus/xxx.txt`。

**整体结构**：一个文件通常包含 `focus_tree = { ... }` 顶层块，内有 `id`、`country`（分配权重）、`continuous_focus_position` 和若干 `focus = { }` 节点。

```text
focus_tree = {
    id = ger_focus_tree
    country = {
        factor = 0                    # 默认权重
        modifier = {
            add = 10                  # GER 使用此树的权重
            tag = GER
        }
    }
    default = no
    continuous_focus_position = { x = 1200 y = 100 }

    focus = {
        id = GER_rearmament
        icon = GFX_goal_generic_construct_military
        x = 5
        y = 0
        cost = 10                      # 每 1 点 = 7 天，10 = 70 天
        available = { ... }            # 可点条件
        bypass = { ... }               # 跳过条件
        completion_reward = { ... }    # 完成效果
    }
}
```

**国策节点关键字段**：

| 字段 | 含义 |
|------|------|
| `id` | 国策唯一 ID（用于引用/本地化） |
| `icon` | 图标 sprite 名（在 `.gfx` 中定义） |
| `x` / `y` | 绝对坐标 |
| `relative_position_id` | 相对定位：以另一国策为原点 |
| `prerequisite = { focus = A }` | 前置国策（多个 prerequisite 块=需全部完成，实线；单个块内多个 focus=完成任一即可，虚线） |
| `mutually_exclusive = { focus = B }` | 互斥国策 |
| `cost` | 所需天数（1 = 7 天） |
| `available` | 可点击条件 |
| `bypass` | 自动跳过条件 |
| `available_if_capitulated` | 投降后是否可点 |
| `cancel_if_invalid` / `continue_if_invalid` | 条件失效时取消/继续 |
| `will_lead_to_war_with` | 提示将向某国宣战 |
| `allow_branch` | 满足条件才显示此分支（配合 `mark_focus_tree_layout_dirty = yes`） |
| `search_filters` | 国策搜索筛选标签 |
| `completion_reward` | 完成时效果 |
| `ai_will_do` | AI 选择倾向 |

**搜索筛选标签**（`search_filters`）常用值：

```text
FOCUS_FILTER_POLITICAL     政治
FOCUS_FILTER_RESEARCH      科研
FOCUS_FILTER_INDUSTRY      工业
FOCUS_FILTER_STABILITY     稳定度
FOCUS_FILTER_WAR_SUPPORT   战争支持度
FOCUS_FILTER_MANPOWER      人力
FOCUS_FILTER_ANNEXATION    吞并
```

**共享国策**：`shared_focus = { ... }` 定义不需要国策树直接生效的国策；`shared_focus = 国策id` 调用共享国策。

### 5.2 持续国策 `common/continuous_focus/`

**作用**：定义底部持续执行的国策（如"建筑工业"）。结构与普通国策类似，通过 `continuous_focus_position` 定位。

## 六、事件与决议

### 6.1 事件 `events/`

**作用**：定义游戏运行时弹出的事件。位置在顶层 `events/` 目录（注意不是 common 内）。

**结构**：顶层 `add_namespace = xxx` 定义命名空间，事件 ID 为 `xxx.N`。

```text
add_namespace = my_mod

country_event = {                      # 国家事件
    id = my_mod.1
    title = my_mod.1.t
    desc = my_mod.1.d
    picture = GFX_report_event_generic
    is_triggered_only = yes            # 仅供调出（不会自动触发）
    fire_only_once = yes               # 仅触发一次
    hidden = yes                       # 隐藏弹出（配合 immediate）
    trigger = { ... }                  # 自动触发条件
    immediate = { ... }                # 事件弹出同时立即执行的效果
    option = {                         # 事件选项
        name = my_mod.1.a
        ai_chance = { factor = 100  modifier = { factor = 0  has_war = yes } }
        add_political_power = 100
    }
}
```

**关键字段**：

| 字段 | 含义 |
|------|------|
| `id` | 事件 ID（`命名空间.编号`） |
| `title` / `desc` | 标题/描述（本地化键） |
| `picture` | 事件图片 |
| `is_triggered_only` | 只被其他效果调出，不自动触发 |
| `fire_only_once` | 全局只触发一次 |
| `hidden` | 隐藏（不显示弹窗，常配合 immediate） |
| `trigger` | 自动触发条件 |
| `mean_time_to_happen` | 平均触发时间（MTTH，随机触发用） |
| `immediate` | 弹出瞬间执行 |
| `option` | 选项（可多个），`ai_chance` 控制 AI 选择 |

**其他事件类型**：`news_event`（新闻事件，供 `news_event = { id = ... }` 调出）、`super_event`（超事件）。

**调出事件**：

```text
country_event = { id = my_mod.1 days = 3 random = 12 }   # 3 天后 ±12 小时弹出
news_event = { id = my_mod.2 }
```

### 6.2 决议 `common/decisions/`

**作用**：定义玩家可主动点击的决议（Decision）。

**分类文件**：`common/decisions/categories/xxx_decision_category.txt`

```text
XX_decision_category = {
    icon = 图标名
    picture = 图片名
    allowed/available/visible = { ... }
    priority = 优先度              # 越高越靠上
}
```

**单个决议**：`common/decisions/xxx.txt`

```text
XX_decision_category = {             # 分类块
    my_decision = {                  # 单个决议
        icon = GFX_decision_xxx
        cost = 50                    # 政治点消耗
        days_remove = 30             # 决议持续天数
        days_re_enable = 60          # 完成后多少天可再点
        fire_only_once = yes         # 只能点一次
        allowed/available/visible = { ... }
        ai_will_do = { factor = 1 }
        modifier = { ... }           # 决议进行中的持续修正
        complete_effect = { ... }    # 点击时效果
        remove_effect = { ... }      # 移除时效果
    }

    my_mission = {                   # 任务模板（mission）
        activation = { ... }         # 触发任务的条件
        available = { ... }          # 完成任务的条件
        is_good = yes                # 进度条颜色
        days_mission_timeout = 30    # 任务时限
        timeout_effect = { ... }     # 超时效果
        complete_effect = { ... }    # 完成效果
    }
}
```

**visible / allowed / available 区别**：

| 字段 | 检测时机 | 用途 |
|------|----------|------|
| `visible` | 随时检测 | 是否显示该决议 |
| `allowed` | 仅开局检测 | 是否可用（显示灰） |
| `available` | 随时检测 | 是否可点击执行 |

**限时/任务决议纪律（对照 RHoiScribe 补全 F）**：
- 任务块用 `days_mission_timeout`（时限）+ `timeout_effect`（超时效果）+ `cancel_trigger`（可中途取消）；
- 链式任务用旗标/变量做状态机，避免覆盖导致的重复触发漏洞；AI 行为用 `ai_will_do` 控制重复点击；
- `complete_effect` 触发下一环时用 `country_event = { ... days = N }` 延迟串联。

## 七、民族精神与理念

### 7.1 民族精神 / 法案 / 内阁 `common/ideas/`

**作用**：定义民族精神（National Spirit）、法案（Law）、内阁（Political Advisor）等。文件位置 `common/ideas/`。

**结构**：顶层 `ideas = { ... }`，可含分组。

```text
ideas = {
    my_idea = {
        allowed = { tag = GER }       # 使用条件
        modifier = {
            stability_weekly = 0.01
            research_speed_factor = 0.05
        }
        ai_will_do = { factor = 10 }
        removal_cost = -1             # 移除消耗（-1 = 不可移除）
    }
}
```

**法案（Law）** 需加 `law = yes` 与 `use_list_view = yes`：

```text
ideas = {
    conscription_law = {              # 兵役法案分组
        law = yes
        use_list_view = yes
        volunteer_only = {            # 志愿兵役
            removal_cost = -1
            modifier = { ... }
        }
        limited_conscription = { ... } # 有限征兵
    }
}
```

> **注意**：法案需在 `common/idea_tags`（或 `00_idea`）中注册 `slot = 法案名字`，否则不生效。

**隐藏民族精神**：把 `ideas` 替换为 `hidden_ideas`，下面放民族精神即可。

## 八、角色与国家领袖

### 8.1 角色 `common/characters/`

**作用**：新版人物系统，统一管理领导人、顾问、将领（元帅/将军/海军将领）。文件位置 `common/characters/xxx.txt`。

```text
characters = {
    DOH_leader = {
        name = DOH_leader_name          # 本地化词条
        portraits = {
            army = {
```

### 12.6 特殊案例：TNO 行政区划（Admin_Title）体系

> 本项为 TNO 专用框架的**设计模式**，非原版机制；完整原理见
> `E:\QIUQI-LIBRARY\资料\基础代码\特殊案例\TNO行政区划系统运作原理.md`（882 行）。
> 这里仅登记模式摘要，供做"州级行政区划"类 mod 时复用思路。

- **存储**：每个 `history/states/*.txt` 的州上存 5 个变量——`AdminTitle`（一级区划 token）、
  `AssocRegion`（主关联区域）、`AssocRegion2`（次关联区域）、`SubAdminTitle`（下级区划）、
  `SubDivisions`（下级数量 int）。
- **注册**：`common/ideas/admin_title_ideas.txt` 为每个 token 注册隐藏 idea，
  `on_add` 把 token 的 EndoExo 属性写进全局数组。
- **分配**：`common/scripted_effects/admin_title_<洲>_effects.txt` 按大洲初始化各州 title；
  中国等用间接索引变量（`china_state_ref`/`china_region_ref`/`china_city_ref`）+ `on_startup` 转换。
- **显示**：`common/scripted_localisation/` 的 `defined_text` 做**多层后缀拼接**
  （GUI/Textbox/MapMode 三套链），`common/scripted_guis/TNO_admin_title.txt` 承载州视图 UI。
- **控制权变更**：`common/on_actions/TNO_on_state_control_changed_actions.txt` 按 token 调用
  `TNO_admin_title_state_control_effect_[TOKEN]` 处理交接。
- **地图模式**：`common/map_modes/*.txt` 的 `scripted_map_modes` 按选中州类型着色。

> 通用启示：州级自定义"标签体系" = 州上 token 变量 + hidden idea 注册 + scripted_localisation 拼接 +
> map_modes 着色 + state_control 交接；这套模式可复用到任意"给州打标签"的需求。

## 十五、AI 体系

AI 相关文件统一放在 `common/` 下的多个子目录，控制 AI 国家的战略、生产、科研、部队等行为。

### 15.1 AI 战略倾向 `common/ai_strategy/`

**作用**：定义 AI 的外交/军事/生产战略策略组。核心是 `ai_strategy = { type = ... id = ... value = ... }`。

```text
my_strategy = {
    enable = { ... }            # 开启条件（可无限重复）
    abort = { ... }             # 终止条件
    abort_when_not_enabled = yes
    ai_strategy = {
        type = unit_ratio       # 战略种类
        id = infantry           # 执行对象
        value = 100             # 倾向值
    }
}
```

**常用战略种类（type）**：

| type | 含义 |
|------|------|
| `alliance` | 与某国结盟（id 需引号） |
| `antagonize` / `befriend` / `contain` / `protect` / `support` | 外交态度 |
| `declare_war` | 有战争目标即宣战 |
| `conquer` | 鼓励征服某国 |
| `prepare_for_war` | 对某国准备战争 |
| `invade` | 海上入侵 |
| `send_volunteers_desire` / `send_lend_lease_desire` | 派遣意愿 |
| `unit_ratio` | 兵种训练比率 |
| `role_ratio` | 模板角色训练倾向 |
| `template_prio` | 兵种模板训练倾向 |
| `equipment_production_factor` | 装备生产倾向 |
| `equipment_stockpile_surplus_ratio` | 装备储备比例 |
| `building_target` | 建筑倾向 |
| `force_build_armies` | 强制造兵 |
| `spare_unit_factor` | 备用部队 |
| `front_control` / `front_unit_request` | 前线控制/部署 |
| `garrison` / `garrison_reinforcement_priority` | 驻军 |
| `research_tech` | 指定研究科技 |
| `occupation_policy` | 占领策略 |

### 15.2 AI 战略计划 `common/ai_strategy_plans/`

**作用**：定义 AI 的国策选择顺序（计划），含 `name`/`desc`、国策顺序列表、高级块（allowed/enable/abort/ai_will_do）。

### 15.3 AI 师模板 `common/ai_templates/`

### 15.9 逆向 AI 策略（Reversed AI Strategy）

**作用**：让 AI 策略的「主动者/被动者」语义反转——`ai_strategy` 里 `id = TAG` 由"目标"变为**主动者**，`enable` 由主动者条件变为**被动者筛选**。文件仍放 `common/ai_strategy/`，加一行 `reversed = yes`。

**各条件块语义（对照 QIUQI《逆向AI策略简明教程》）：**

| 块 | 是否反转 | 检测对象 | 检测次数 | 要点 |
| --- | --- | --- | --- | --- |
| `allowed` | **否** | 主动者 | 开局/载档检测一次 | 必须写主动者**能满足**的条件（如 `always = yes`）；写成被动者条件会导致策略不生效 |
| `enable` | **是** | 被动者 | 每检测一国执行一次 | 满足的每个国家都成为被动者（**可多个**） |
| `enable_reverse` | 无默认作用域 | 任意（常写主动者） | 只执行一次 | 可选；写清作用域可关联第三方（如 `GER = { has_war = yes }`）；**不受 `abort_when_not_enabled` 管控** |
| `abort` / `abort_when_not_enabled = yes` | — | 主动者 | 持续 | 与普通 AI 策略一致 |
| `ai_strategy = { type id value }` | — | `id` 变主动者 | — | 同类 `type` 数值**加减汇总**，所有列出的 `id` 都获得相同倾向结果 |

**完整示例**：

```text
BHR_invade = {
    allowed = { always = yes }                 # 主动者(BHR)必须能满足
    enable = { has_war_with = BHR }            # 与 BHR 交战的国家成为被动者
    enable_reverse = { BHR = { has_template_majority_unit = marine } }
    abort_when_not_enabled = yes
    reversed = yes
    ai_strategy = {
        type = invade
        id = BHR
        value = 100
    }
}
```

**坑点**：
- **不能自指**：同一策略里一个国家不能既是主动者又是被动者（该组合无效）。
- 多 `id` 共享所有 `ai_strategy` 项 → 给非主项写 `value = 0` 仅为占位让其成为主动者。
- `enable` 会被多次执行（性能），尽量把重活放 `enable_reverse`/`abort`。
- 调试：控制台 `imgui show ai_strategy`（逆向策略显示为 `<名> (reverse <被动者tag>)`）；
  `imgui hide ai_strategy` 关闭。

**作用**：定义全局事件钩子（如 `on_startup`、`on_declare_war`、`on_annex`），在特定时机自动执行效果。
每个钩子有**独立作用域**（THIS / ROOT / FROM 不能给全局固定含义），写码时必须查清当前钩子的默认作用域。

```text
    }

    }
```

**钩子分类速查（全部收进本表，勿臆造作用域）**：

| 类别 | 钩子名（节选） | 默认作用域注意 |
| --- | --- | --- |
| 通用/脉冲 | `on_startup`、`on_daily`、`on_weekly`、`on_monthly` | 新游戏首日触发（读档不触发）；`on_startup` 默认**无国家作用域**，需 `ENG = { ... }` 之类手动写国家效果；`on_daily/weekly/monthly` 对每个国家各自执行 |
| TAG 变体 | `on_daily_ENG`、`on_monthly_ENG` 等 | 仅当该 tag 国家存在时执行 |
| 政治/和平 | `on_stage_coup`、`on_coup_succeeded`、`on_government_change`、`on_ruling_party_change`、`on_new_term_election`、`on_before_peace_conference_start`、`on_peaceconference_started`、`on_peaceconference_ended` | 竞选/政变/政府/和平会议作用域各有不同 |
| 外交/战争 | `on_declare_war`、`on_war`、`on_peace`、`on_capitulation(_immediate)`、`on_uncapitulation`、`on_annex`、`on_civil_war_end(_before_annexation)`、`on_puppet`、`on_liberate`、`on_release_as_free(_as_puppet)`、`on_guarantee`、`on_military_access`、`on_offer_military_access`、`on_call_allies`、`on_join_allies`、`on_lend_lease`、`on_incoming_lend_lease`、`on_send_expeditionary_force`、`on_return_expeditionary_forces`、`on_request_expeditionary_forces`、`on_ask_for_state_control`、`on_give_state_control`、`on_peace_proposal`、`on_send_attache`、`on_send_volunteers`、`on_border_war_lost`、`on_war_relation_added` | 派远征军/租借/宣言等钩子的 THIS/ROOT 语义各不相同 |
| 州/特殊 | `on_state_control_changed`、`on_naval_invasion`、`on_paradrop` | `on_state_control_changed`：ROOT=新控制者、FROM=旧控制者、FROM.FROM=州；`on_naval_invasion`/`on_paradrop` 的 THIS ≠ ROOT |

**关键点**：
- `random_events` 写在脉冲钩子里会在**钩子作用域内**评估事件触发器（随机事件权重 `0` = 大多不触发）。
- 生成任何 OA 前写清：钩子名 / 类别 / 默认作用域 / ROOT / FROM / PREV / OWNER；未知钩子不要凭记忆臆造作用域。
- **避免替换原版 on_actions 文件**：用 mod 自己的 `common/on_actions/*.txt` 增量添加。

```text
# 示例：on_startup 无国家作用域，需手动指定国家
on_startup = {
    effect = {
        ENG = {
            country_event = { id = my_mod.1 days = 365 }
        }
    }
}
on_monthly = {
    random_events = { 1 = my_mod.10 99 = 0 }
}
```

## 十七、本地化与界面资源

### 17.1 本地化 `localisation/`

> 本节内容依据 **QIUQI-LIBRARY `资料/基础代码/代码提词/本地化wiki.txt`**（社区维护的
> HOI4 本地化 wiki 中文翻译）整理，并结合游戏本体文件验证。

**作用**：所有显示文本的中英翻译。按语言分目录（`english/`、`simp_chinese/` 等），`.yml` 文件。

```yaml
l_english:
  my_focus: "My Focus"
  my_focus_desc: "This is a focus."
  my_event.1.t: "Event Title"
  my_event.1.d: "Event description."
  my_event.1.a: "Option A"
```

#### 17.1.1 快速检查表（文件必须满足）

1. 扩展名为 `.yml`。
2. 文件名（去扩展名）必须以语言的**内部名称**结尾，例如 `filename_l_english.yml`（`l` 是小写 L）。
3. 文件必须为 **UTF-8-BOM** 编码（文件开头带 `EF BB BF` 字节序标记）。不满足时游戏会在日志中报错。
4. 文件第一行必须是内部语言名 + 冒号，例如 `l_english:`，把后续键分配给该语言数据库。

#### 17.1.2 语言与文件命名

本地化文件位于 `/Hearts of Iron IV/localisation/`，其下可放任意子文件夹。每种语言一个内部名称与目录：

| 语言 | 内部名 | 目录示例 |
|------|--------|----------|
| 英语 | `l_english` | `localisation/english/filename_l_english.yml` |
| 法语 | `l_french` | `localisation/French/mod_file_l_french.yml` |
| 德语 | `l_german` | `localisation/German/state_names_l_german.yml` |
| 西班牙语 | `l_spanish` | `localisation/Spanish/mod_germany_l_spanish.yml` |
| 巴西葡萄牙语 | `l_braz_por` | `localisation/braz_por/bahrain_l_braz_por.yml` |
| 波兰语 | `l_polish` | `localisation/polish/myfile_l_polish.yml` |
| 俄语 | `l_russian` | `localisation/russian/siberia_l_russian.yml` |
| 日语 | `l_japanese` | `localisation/japanese/kuril_l_japanese.yml` |
| 简体中文（社区惯例） | `l_simp_chinese` | `localisation/simp_chinese/xxx_l_simp_chinese.yml` |

- 文件名必须以语言的内部名称结尾，否则游戏不加载该文件。
- 当前打开的语言在用户目录 `/Hearts of Iron IV/settings.txt` 中设置；除上述列出的语言外，不能直接添加更多语言。
- 文件内容除文件名/语言外，其余键归属取决于**第一行语言节**。

#### 17.1.3 键规则

- 每个条目结构为 `localisation_key: [版本号] "value"`。
- `localisation_key` 通常与数据库条目名相同（如国策 `TAG_focusname` → 键 `TAG_focusname`）；事件等可在数据库条目内显式设置引用键。
- 描述键习惯追加 `_desc`（如 `TAG_focusname_desc`），用于角色、国策、理念、特征等。
- **键不能包含特殊字符**：只能含英文字母、下划线、点、数字；不能含空格；多字节字符（中文）不可作为键。
- 版本号 `0` 仅供 Paradox 内部翻译跟踪，游戏不会读取，可省略。

#### 17.1.4 值规则

- 值必须在**一行**内；多行会破坏文件。换行用 `\n`（反斜杠 + n）。
- 避免在 `\n` 后留空格，否则游戏内会显示为偏移的下一行。
- 引号 `"` 需转义为 `\"`，反斜杠需转义为 `\\`。
- 本地化任何错误（键含特殊字符/空格、缺引号）都会破坏文件，并从语法首次出错处开始停止解析。

#### 17.1.5 覆盖优先级与 `replace` 文件夹

- 同一语言内重复定义同一键属“重叠”，会在 `/Hearts of Iron IV/logs/text.log` 中记录；选中值无明显一致模式，但似乎优先基础游戏文件。
- **`localisation/<lang>/replace/`** 文件夹内的文件优先级高于普通条目：只覆盖指定键而不必移植整个文件。例如只改某个 effect 名称时，可在 `localisation/english/replace/` 新建文件定义 `POLITICS_ADD_POLITICAL_POWER`，即可覆盖而无需复制整个 `effects_l_english.yml`（该文件经常随游戏更新增加新 effect）。

```yaml
l_english:
  POLITICS_ADD_POLITICAL_POWER: "Political Power: $VAL|=+0$."
```

#### 17.1.6 特殊字符

##### 着色字符

文本可用着色字符改变颜色：以 `§` 开头、以 `§!` 结束。

| 写法 | 效果 | 默认颜色 (R,G,B) |
|------|------|------------------|
| `§!` | 结束当前格式规则 | — |
| `§C` | 青色 | (35, 206, 255) |
| `§L` | 脏橙色灰（淡紫） | (195, 176, 145) |
| `§W` | 白色 | (255, 255, 255) |
| `§B` | 蓝色 | (0, 0, 255) |
| `§G` | 绿色 | (0, 159, 3) |
| `§R` | 红色 | (255, 50, 50) |
| `§b` | 黑色 | (0, 0, 0) |
| `§g` | 浅灰 | (176, 176, 176) |
| `§Y` | 黄色 | (255, 189, 0) |
| `§H` | 黄色（同 `§Y`，标题） | (255, 189, 0) |
| `§T` | 白色（同 `§W`，标题） | (255, 255, 255) |
| `§O` | 橙色 | (255, 112, 25) |
| `§0`~`§9` | 渐变步骤 0~9 | 见下 |
| `§t` | 鲜红（渐变步骤 10） | (255, 76, 77) |

渐变步骤颜色：`§0` 紫 (203,0,203)、`§1` 淡紫 (128,120,211)、`§2` 蓝 (81,112,243)、
`§3` 灰蓝 (81,143,220)、`§4` 浅蓝 (90,190,231)、`§5` 暗青 (63,181,194)、
`§6` 绿松石 (119,204,186)、`§7` 浅绿 (153,209,153)、`§8` 橙黄 (204,163,51)、
`§9` 白橙 (252,169,125)、`§t` 鲜红 (255,76,77)。

示例：

```yaml
l_english:
  example_key: "This is my text, §Bthis text is blue§!, and §Rthis text is red§!"
```

- 可通过扩展 `interface/core.gfx` 的 `textcolors = {}` 数组添加新文本颜色；颜色键只能是一个字母，且会用相同首字母互相覆盖。
- 使用特定字体位图定义时，着色字符可表示与默认不同的颜色。

##### 着色错误

错误信息不提供文件位置，排查方式：

| 错误 | 含义 |
|------|------|
| `Could not find coloring for character 'M'` | 找到 `§M`，但 M 不是有效颜色字符 |
| `Could not find coloring for character id '17'` | 提供了字符 ID（如数字 `1` → id 17，因为数字从 0 计数） |

特例：字符 ID `0` 指 NULL 字符（不是空格），即 `§` 后没有任何字符、字符串以 `§` 结尾；通常是漏了结束的 `§!`（写成 `"§§!"`）。

#### 17.1.7 嵌套文本与引用

- `$KEY$` 引用另一本地化键的值，可嵌套（如 `ITA_balance_of_power_category: "$ITA_power_balance$"`）。
- `£KEY` 为文本化图标 token（如 `£GFX_power_balance_texticon`）。

```yaml
l_english:
  ITA_power_balance: "National Balance of Power"
  ITA_balance_of_power_category: "$ITA_power_balance$"
```

#### 17.1.8 命名空间（namespace）

命名空间用于批量引用本地化/脚本键，减少冲突并便于维护。具体机制见社区 wiki 命名空间章节；本项目按常规键名规范（类型前缀 + 实体名）即可避免大多数冲突。

#### 17.1.9 脚本化本地化

动态生成本地化文本通过 `common/scripted_localisation/` 实现，详见 [16.2 脚本化本地化](#162-脚本化本地化-commonscripted_localisation)。模板见 `templates/系统模板/脚本化本地化/`。

#### 17.1.10 本项目编辑器覆盖情况

- `translation_editor.py` / `TranslationEditDialog`：按类型编辑 name/desc（国策/理念等专用文件），自动写 `_desc`。
- `localisation_editor_dialog.py`：全量词条浏览/新增/编辑/删除、批量补写缺失、多语言（默认中文，英文可选）、分类筛选。
- `quick_localisation_edit.py`：各编辑器右键小窗口快速编辑当前键（BOP 含名称+描述）。
- 写回统一 `atomic_write_text(..., encoding="utf-8-sig", allow_bom=True)`，遵循 BOM 契约。

### 17.4 脚本化 GUI `common/scripted_guis/`

**作用**：在 .gui 之外用 PDX 脚本生成动态界面（设计器/联名面板/自定义窗口等）。文件放 `common/scripted_guis/*.txt`。

```text
scripted_gui = {
    my_gui = {
        context_type = decision_category
        window_name = "my_window"            # 必须已存在于 interface/*.gui
        properties = { ... }                 # 属性（image / [GET_SCRIPTED_LOCATION] 引用）

            }
        }
    }
}
```

**校验纪律**：`window_name` 必须存在于 `.gui`；可见触发器要便宜；动态列表计算前用 `clear_temp_array` 清空并重建临时数组；GUI 元素名与 trigger/effect/property 引用完全一致。

## 十八、编写规范与常见错误

### 18.1 编码与格式契约

| 项目 | 规范 |
|------|------|
| 脚本文件编码 | UTF-8 无 BOM，LF 换行 |
| 本地化 `.yml` | UTF-8 **带 BOM**（`utf-8-sig`） |
| 注释 | `#` 到行尾 |
| 字符串 | 含空格/特殊字符必须加英文双引号 |

### 18.2 常见错误

1. **括号不配对**：缺 `}` 或多 `}`，是 Mod 最常见的崩溃/加载失败原因。
2. **引号错误**：中文引号、未闭合引号。
3. **ID 重复**：国策/科技 ID 跨文件重复会冲突。
4. **本地化缺失**：实体（国策/事件/决议/理念等）无对应词条，游戏内显示为 key。
5. **前置国策悬空**：`prerequisite` 引用了不存在的国策。
6. **sprite 未注册**：图标名在 `.gfx` 中无定义，或贴图路径不存在。
7. **编码问题**：本地化文件缺 BOM 导致中文乱码。

### 18.3 引用完整性检查清单

发布前应检查：

- `.mod` 描述文件存在，`path` 指向的目录存在，有 `name` 字段
- 全部脚本文件为合法 UTF-8、括号配对
- `interface/*.gfx` 定义的 sprite 贴图存在（mod 内或游戏本体回退）
- 国策 prerequisite 无悬空引用
- 科技图标 sprite 已注册
- 本地化词条完整（mod + 游戏均无时报告）
- 国策/科技 ID 无跨文件重复

### 18.4 数组与临时数据结构

数组存放作用域或值列表（常用于脚本化 GUI 动态列表与重复脚本操作），需明确**属主作用域与重置行为**：

```text
clear_temp_array = temp_items
add_to_temp_array = { array = temp_items value = mtth:score_1 }
is_in_array = { array = ROOT.my_array value = THIS }
temp_items^index
```

校验：重建前先清临时数组；`dynamic_lists` 里定义索引/值名；区分数组值是作用域还是数字。

### 18.5 唯一标识符纪律（unique identifiers）

创建以下**可复用标识符**前，应做跨 mod + game 的重复扫描（引用已有内容属信息性，只把“创建意图”当重复风险）：

- 角色 / 旗标 / TAG / 理念 token / 动态修正 / 国策 / 决议 / 事件命名空间 / 脚本化效果 / 触发器 / Character。
- **国策 ID 区分**：`focus = { id = ... }`、`shared_focus = { id = ... }`、`joint_focus = { id = ... }` 是**国策节点 ID**；`focus_tree = { id = ... }` 是**国策树 ID**，切勿混淆。
- **旗标族区分**：`country_flag / global_flag / state_flag / character_flag / mio_flag / project_flag`（`unit_leader_flag` 归 legacy character 旗标族）。
- 生成的文件/目录/脚本标识符保持 **ASCII**（本地化文案是唯一正常例外）。
- `replace_path` 会隐藏原版文件夹，计划写入其下路径时应提示。
