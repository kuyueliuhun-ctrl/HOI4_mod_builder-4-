## 2. 评分模型

对每个 UI 按 5 个维度打 1–5 分：

- **展示 D**：能否呈现该文件 100% 字段/块（含回退到树编辑器的等效路径）
- **编辑 E**：新建/编辑/删除/保存是否齐备
- **保留 K**：未知/未建模字段是否无损保留（不丢数据）
- **易用 U**：搜索/撤销/批量/反馈/布局是否人手友好
- **规范 C**：写入纪律/四层分离/编码等契约是否合规

分级：`★=完全依赖兜底`、`★★★=可日常使用`、`★★★★★=接近零缺口的专业级`

## 4. 人类易用性总评（优点）

1. **中文优先 + 本地化联动**：几乎所有实体列表/下拉/tooltip 优先中文（mod→游戏→词条库回退），本地化键可直接改中文名。
2. **无损心智**：树编辑器原始格式保留、块级替换、原版自动落 mod——用户不用担心改坏文件或污染游戏本体。
3. **反馈充分**：编辑器普遍带 tooltip/消息框（BOP 16、编制 32、设计器 29、地图 19）；实时统计（编制地形、BOP 区间修正、地图信息面板）。
4. **固定布局**：AI 侧栏 300px 无横向滚动、地图/设计器右面板 setFixedWidth(330) 防抖动。
5. **批量与快捷键**：本地化批量补写、图标批量、DDS 批量；树编辑器 Ctrl+Z/Ctrl+F/Ctrl+Return。

## 5. 现有人类易用性问题（改进建议，按优先级）

| 级别 | 问题 | 建议 | 是否需拍板 |
| --- | --- | --- | --- |
| P1 | **大文件打开慢**：PDX 树解析对 vanilla 大文件（defines.lua / 巨型国策/事件文件）耗时高，沙箱抽样直接卡死 | 打开超限文件走惰性/增量解析 + 进度提示；或先只载入树骨架 | 否（性能优化） |
| P1 | **快捷键不统一**：仅树编辑器有 Ctrl+F/Ctrl+Z；其他编辑器无标准保存/查找/复制 | 统一 `Ctrl+S` 保存、`Ctrl+F` 查找、`Ctrl+Z` 撤销到各专用编辑器 | 否 |
| P1 | **角色编辑器 roles 不可见**：只显示个数，用户要在树编辑器里翻 | 增加只读 roles 块预览/折叠展示（或一键转到对应行） | 需拍板（UI 形态） |
| P2 | **保存后撤销不一致**：部分编辑器保存后不可窗口级撤销（undo_mgr 覆盖画布+写操作，未覆盖编辑器内字段编辑） | 设计器/本地化编辑器内字段编辑引入本地撤销栈 | 否 |
| P2 | **多入口分散**：本地化编辑/快速本地化/实体资源工作台三处进入方式不同 | 加统一"本地化入口"引导（最近键值/差异统计） | 需拍板 |
| P2 | 编辑写入前无 diff 预览（除覆盖规则报告） | 批量写前给"改动摘要/受影响的文件清单"确认框 | 否 |
| P3 | 无文件模式下国家筛选缺少按 tag/区域过滤 | 加筛选下拉 | 否 |
| P3 | 画布撤销与编辑器撤销栈两套，容易混淆 | 统一到 undo_mgr 工厂 | 否 |

## 6. 综合结论

1. **规范符合度：整体合规。** 写入纪律 / 四层分离 / 禁图 / 编码 / 验证门禁全部通过；每类内容都有通用树编辑器兜底，**不存在"数据展示或编辑被丢弃"的违反**。
2. **完整读写（§4.12）分级成立**：通用树编辑器满足字面 100%；专用编辑器多为"子集展示 + 无损保留 + 树编辑器兜底"的**设计取舍**——这符合"可对文件内容进行修改且不丢字段"的本意，但**若干编辑器（角色/BOP/地图）未在自身 UI 展开全部字段**，如实记录为可改进点而非违规。
3. **人类易用性：良好但有短板**。优点集中在中文优先、无损心、反馈丰富、固定布局、批量能力；短板集中在大文件性能、快捷键统一、角色 roles 不可见、保存后撤销。
4. **覆盖扫描工具不可用是本轮一大发现**：`check_ui_coverage.py` 在沙箱对全量 vanilla 树直接超时（PDX 解析器性能瓶颈），建议优先投入 P1-大文件性能优化，之后该工具才能真正成为 §4.12 的持续门禁。
