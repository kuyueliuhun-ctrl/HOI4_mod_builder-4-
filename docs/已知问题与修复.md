## P0-1 mod/vanilla 覆盖顺序颠倒 —— ✅ 已修复

**现象**：多个 loader 写成 `for base in (mod_path, hoi4_path)`，后写覆盖先写，导致**游戏数据覆盖 mod 数据**；注释/文档却写“mod 覆盖游戏”。

**证据**：`oob_loader.py:281,331`；`ship_design.py:163`；`tank_design.py:138`；`plane_design.py:152`；同族的 modules/variants loader 也有相同问题。

**修复**：
- 将下列函数改为「先游戏、后 mod」：
  - `oob_loader.load_sub_units`
  - `ship_design.load_ship_hulls / load_ship_modules / load_ship_variants`
  - `tank_design.load_tank_chassis / load_tank_modules / load_tank_variants`
  - `plane_design.load_plane_airframes / load_plane_modules / load_plane_variants`
  - `designer_slots.load_upgrade_definitions`（同族额外修复，参数顺序为 `hoi4_path, mod_path`）

**回归测试**：`tests/test_p0_fixes.py::ModVanillaOverrideOrderTest`
- `load_sub_units` / ship hull / tank chassis / plane airframe / upgrade definitions 均验证 mod 值覆盖游戏值。

## P0-2 PDX 解析器静默损坏数据 —— ✅ 已修复

**现象**：
- 字符串里的 `#` 被当注释截断（`"color #FFFFFF"` → `"color"`）；
- 分词正则丢掉 `@ : + / ( ) ,`；
- 未闭合引号、多余 `}` 被静默吞掉。

**证据**：`pdx_parser.py:24,29,48-49`（修复前）。

**修复**：
- 新增 `_strip_comments()`：只在引号外剥离 `#` 注释；未闭合引号抛 `ValueError`。
- 分词正则改为 `[^\s\{\}=<>#]+`，保留 `@ : + / ( ) ,` 等无引号字符。
- `parse_block` 增加 `top` 标记：顶层多余 `}` 抛错；嵌套块未闭合 `{` 抛错。

**回归测试**：`tests/test_p0_fixes.py::PdxParserCorruptionTest`

## P0-3 接口层任意文件读写/可改写游戏本体 —— ✅ 已修复（含收口项）

**现象**：`country / filename / tag / icon_base / path` 多处未做路径/字符校验，HTTP/MCP 持 token 可越出 mod 目录写任意文件；OOB 写路径可直接就地改原版。

**证据**：`api_server.py:322,490,531`；`generators.py:15`；`designers.py:492-516`；`media.py:40`。

**修复**：
- 新增共享安全模块 `src/path_safety.py`：
  - `validate_component()`：单段文件名字段校验（拒绝分隔符 / `..` / 盘符 / 以数字开头）。
  - `safe_join()`：mod 内相对路径拼接，拒绝绝对路径 / `..` / 盘符 / 符号链接逃逸。
  - `is_within()`：判断绝对路径是否在 root 内。
- 接入入口：
  - `api_server.create_entity`：`country` 校验。
  - `api_server.create_focus_project`：`country`、`focus_id` 校验。
  - `api_server.write_localisation`：`tag` 校验。
  - `project_wizard._write_loc_entries`：`tag` 校验（纵深防御）。
  - `api_core_ext.generators._gen_files`：`filename` 校验。
  - `api_core_ext.media.upload_entity_icon`：`icon_base` 校验。
  - `api_core_ext.media.generate_gui_gfx_asset`：`name` / 输出路径校验。
  - `api_core_ext.media.convert_dds`：只允许 mod 内相对路径，`output_dir` 也限 mod 内。
  - `api_core_ext.designers._oob_read_path / _oob_write_path`：OOB `rel` 必须通过 `_safe_join` 校验，不再可直接解析到游戏原文件。
  - `country_setup_dialog.create_new_country_files`：`tag` 校验。
  - `api_server._safe_join` 改用 `path_safety.safe_join`，现有安全入口也补上符号链接检查。

**回归测试**：`tests/test_p0_fixes.py::PathSafetyTest`

**收口项（2026-08-26 已全部完成）**：
- ✅ `api_server.analyze_error_log`：`absolute_path` 仅限 mod/game 根内（`path_safety.is_within`），任意文件读取已封堵；`path`（相对 mod）沿用 `_safe_join`。
- ✅ `api_core_ext.media.import_unit_counters`：`output_dir` 必须为 mod 内相对路径（`_safe_join` 校验），拒绝绝对/`..` 越界。
- ✅ `project.create_mod`：非 dry_run 需 `approved=true` 确认；`mod_folder_path`/`mod_file_path` 限制在 settings 白名单根（`mod_folder_path`/`mod_file_path`）与当前 mod 父目录内。
- 回归：`tests/test_p0_fixes.py::P0FollowupSecurityTest`（5 例，含拒绝任意绝对读 / 越界 output_dir / create_mod 未批准与越界路径拒绝）。

## P0-4 撤销功能丢 BOM/CRLF、失败丢条目 —— ✅ 已修复

**现象**：
- 快照按 `utf-8-sig + errors="ignore"` 读，写回默认 UTF-8，撤回后 BOM/CRLF 丢失；
- `undo()` 先 `pop()` 再写，写失败则撤销条目永久丢失。

**证据**：`undo_mgr.py:27,46-53`；`write_utils.atomic_write_text` 默认编码。

**修复**：
- `FileUndoManager.before_write` 改为读取**原始字节**快照。
- 新增 `write_utils.atomic_write_bytes()`，撤销时按原始字节无损恢复 BOM/CRLF/编码。
- `undo()` 改为成功后 `pop()`；失败时保留栈顶条目。

**回归测试**：`tests/test_p0_fixes.py::UndoManagerLosslessTest`

## P0-5 OOB 保存写坏文件 —— ✅ 已修复

**现象**：
- `save_names_group` 替换命名组后丢外层 `}`；
- 无 `name` 字段的模板被当“已删除”删掉，随后重写并加 `name=""`。

**证据**：`oob_loader.py:1006,626-638`。

**修复**：
- `save_names_group` 不再使用 `_block_ranges` 对“最后一个子块”的近似 end，改为精确匹配组块闭合 `}`，替换后保留外层 `}`。
- `OobFile.save` 的模板匹配支持“无 name 字段”的模板：`name` 为空时，块内没有 `name = "..."` 也能匹配，避免误删重写。

**回归测试**：`tests/test_p0_fixes.py::OobSaveCorruptionTest`

**附带收口（2026-08-26）**：`oob_loader._clear_oob_caches()` 原用自身 `globals()` 查
`_EQUIP_STATS_CACHE`（实际定义在 `oob_stats.py`）→ 永远 `None`，清理为 no-op；
改为 `oob_stats.clear_equip_stats_cache()` 真清缓存（回归：`P0FollowupSecurityTest::test_oob_equip_cache_clear_not_noop`）。
