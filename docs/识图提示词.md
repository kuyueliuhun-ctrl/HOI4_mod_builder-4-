# 识图提示词（配合 AI 助手使用）

> 用途：主 AI 无法直接读图时，用「外部多模态模型」替你识别截图，
> 再把识别结果粘贴回主 AI，主 AI 基于结果继续设计/修改。
>
> 用法：
> 1. Windows 上截图（或让主 AI 在沙箱渲染出 PNG）
> 2. 把图片 + 下方任一提示词一起发给多模态模型（ChatGPT / 通义 / 豆包 / Claude 等）
> 3. 把它的**原样输出**粘贴回主 AI 对话框
>
> 提示词里要求模型输出 **JSON 代码块**（便于主 AI 直接解析），
> 坐标一律用**原图像素**，颜色一律用 **RGB**，中文回答。

---

## 一、通用界面截图验收（最常用）

```
你是一名 UI 验收工程师。这是某桌面软件界面的截图。请仔细检查并输出：

1. 布局问题：元素错位、重叠、遮挡、超出边界、间距异常（给出具体区域和大致像素位置）
2. 文字问题：文字溢出按钮/面板、被截断、换行异常、乱码、方框占位符（给出具体文字内容）
3. 视觉问题：颜色突兀、对比度过低看不清、图标模糊或变形（给出颜色 RGB 和位置）
4. 图标问题：图标与文字不对应、重复、缺图（黑块/空白）
5. 其他明显异常

只报告【确实存在的问题】，不要报告正常现象。
最后输出：
1. 一段话总结（50 字内）
2. JSON 代码块，格式如下（无问题则 issues 为空数组）：

{
  "summary": "一句话总结",
  "issues": [
    {
      "type": "layout|text|visual|icon|other",
      "position": "左上角约(x,y)，或『右侧面板中部』等描述",
      "detail": "具体问题描述",
      "expect": "应如何"
    }
  ]
}
```

## 二、地图渲染验收（地图编辑器专用）

```
你是一名游戏地图渲染验收工程师。这是钢铁雄心4风格的地图编辑器截图。请检查：

1. 边界锐利度：省份边界是否清晰锐利（有无模糊、锯齿、断线、错位重影）
2. 颜色区分：相邻省份颜色是否容易区分；国家色是否正常（不是全灰/全黑/刺眼色）
3. 高亮醒目度：图中如果有青色高亮（悬停）和黄色高亮（选中）的省份，
   判断它们是否足够醒目、能否一眼看出；边缘是否有白色描边
4. 瓦片异常：是否有整块色差、接缝、内容缺失、模糊的马赛克区域
5. 图例/文字：地图上的标签文字是否清晰可读、有无重叠
6. 缩放观感：画面是否过度放大/缩小、留白是否异常

输出格式同通用要求：一段话总结 + JSON 代码块
{
  "summary": "一句话总结",
  "issues": [
    {
      "type": "border|color|highlight|tile|label|zoom|other",
      "position": "像素位置或区域描述（如『地图中部偏左』）",
      "detail": "具体问题",
      "expect": "应如何"
    }
  ]
}
```

## 三、建筑图标按钮区检查（左侧按钮面板）

```
这是一张软件界面截图，左侧是建筑类型的图标按钮网格。请检查：

1. 每个图标按钮是否都显示正常（有无空白、黑块、模糊、拉伸变形）
2. 图标之间是否错位（同一行的图标是否对齐，有无上下偏移）
3. 图标内容是否与按钮应有含义匹配（如军事建筑图标不像军事建筑）
4. 图标是否超出按钮边界或被裁剪
5. 下方文本按钮的文字是否完整显示、有无截断
6. 悬停提示是否可见（如果截图含 tooltip）

输出格式同通用要求（type 用 icon|layout|text|other）。
```

## 四、设计器界面验收（师编制/舰艇/飞机/坦克设计器专用）

```
你是一名游戏 UI 验收工程师。这是钢铁雄心4 MOD 编辑器某个设计器（编制/舰艇/飞机/坦克）的截图。请检查：

1. 槽位布局：槽位卡片是否按网格整齐排列、有无错位/重叠/超出面板；固定槽与可换槽是否容易区分
2. 锁定槽：被锁定（🔒）的槽是否呈禁用态、不可点击，图标/文字是否清晰
3. 空配件提示：如果设计未配置模块，顶部是否显示“该设计未配置模块，游戏使用默认配置”之类的橙色提示
4. 数据面板：右侧属性数值是否对齐、单位/百分比是否正常、有无被截断或溢出
5. 顶部控件：国家/设计下拉、改名框、新建/复制/删除/保存按钮是否完整可读
6. 同款同步：如果截图含“同款 N 国”标签或“同步到所有同款”按钮，文字是否完整、位置是否合理
7. 整体风格：亮色主题是否统一，颜色对比是否清晰，有无深色残留或突兀色块

输出格式同通用要求：
{
  "summary": "一句话总结",
  "issues": [
    {
      "type": "layout|text|visual|icon|other",
      "position": "像素位置或区域描述（如『槽位区第3行』『右侧面板中部』）",
      "detail": "具体问题",
      "expect": "应如何"
    }
  ]
}
```

## 六、界面设计还原（参考图 → 设计规格，用于「照着这个界面设计」）

适用：你想参考某张图片（别的软件界面、游戏内界面、竞品截图、手绘草图）来设计
本项目的界面。多模态模型把图片还原成**设计规格**，主 AI 依据规格直接设计。

核心原则：**内容必须精准（逐字、逐色、逐图标），布局可以粗略（区块+比例即可）**。

### 完整版

```
你是一名 UI 设计师，正在把一张界面截图还原成可交付给开发者的设计规格。
请遵循：内容层必须精准——所有文字逐字准确、颜色给精确 RGB、图标逐一描述；
布局层可以粗略——只要区块划分、大致比例（百分比）和层级关系。

请按以下结构输出（必须输出 JSON 代码块，不要额外解释）：

{
  "style": "整体风格一句话，如『深色专业工具风，红黑配色，军事感』",

  "layout": {
    "structure": "粗略结构描述，如『顶部菜单栏；左侧窄栏(约15%)；中部画布(约70%)；右侧面板(约15%)；底部状态栏(高约30px)』",
    "regions": [
      {"name": "区域名", "position": "top|left|right|bottom|center|modal",
       "approx_ratio": "占屏约 x%", "role": "该区域做什么"}
    ]
  },

  "colors": {
    "background": {"main": "RGB", "secondary": "RGB"},
    "panel": {"bg": "RGB", "border": "RGB"},
    "accent": {"primary": "RGB", "hover": "RGB", "selected": "RGB"},
    "text": {"primary": "RGB", "secondary": "RGB", "disabled": "RGB"},
    "danger_warning": "RGB 或 null",
    "notes": "色彩使用规律，如『标题用主色，选中项底色为半透明主色』"
  },

  "typography": [
    {"role": "窗口标题|区块标题|按钮|正文|标签|状态栏…", "size_guess": "约多少px",
     "weight": "bold|normal", "style": "italic 或无", "serif": true/false,
     "color": "RGB", "sample": "图中实际文字示例"}
  ],

  "components": [
    {"type": "按钮|输入框|下拉|滑块|复选框|表格|树|标签页|卡片|列表|图标按钮|工具栏…",
     "location": "所在区域", "count": "数量或n个",
     "appearance": "外观要点（圆角、边框、底色、图标风格）",
     "content": "上面的文字/图标内容"}
  ],

  "text_content": {
    "all_visible_text": ["逐条列出图中所有可见文字，必须逐字准确，包括按钮、标题、提示、数字、占位符"],
    "truncated_or_unclear": ["看不清/被截断的文字，注明位置"]
  },

  "icons": [
    {"location": "位置", "guess": "图标表示什么（如『齿轮=设置』『旗帜=国家』）",
     "style": "线性/填充/拟物，主色RGB，尺寸感", "certainty": "high|medium|low"}
  ],

  "decoration": {
    "corner_radius": "圆角程度（无/小/大）",
    "shadow": "有无阴影、深度",
    "separators": "分隔线样式与位置",
    "gradient": "有无渐变及颜色",
    "spacing": "间距规律（紧凑/宽松）"
  },

  "states": {
    "hover": "悬停态样式（若有）",
    "selected": "选中态样式（若有）",
    "disabled": "禁用态样式（若有）"
  },

  "layout_notes": "布局上值得注意的对齐、分组、留白习惯（粗略即可）"
}
```

### 快速版（贴图即用）

```
把这张界面截图还原成设计规格。规则：内容必须精准（所有文字逐字准确、颜色给精确
RGB、图标逐一描述），布局粗略即可（区块+百分比）。输出 JSON 代码块，字段：
style(风格一句话)；layout(structure 粗略结构 + regions 区域列表)；
colors(background/panel/accent/text 各 RGB)；typography(文字层级列表)；
components(控件列表：类型/位置/外观/内容)；text_content(所有可见文字逐字列出 +
看不清的注明位置)；icons(位置/含义猜测/风格/置信度)；decoration(圆角/阴影/分隔线/
间距)；states(悬停/选中/禁用态)。只描述图中真实存在的，不要编造。
```

## 七、输出约定（粘贴回主 AI 前）

- **原样粘贴**多模态模型的输出即可，不要转述、不要删减 JSON
- 如果模型输出明显离谱（如把地图说成照片），可注明「模型可能误判，请仅采用明显可靠的部分」
- 一张图一个问题反复出现时，issues 里合并为一条并说明出现范围

## 八、按 UI 评分清单逐项识别（配合 Qwen3.7plus / 多模态模型）

> 使用场景：用户已对 `docs/UI评分清单.md` 打分；把每个界面的截图按清单 ID 发给多模态模型，
> 让它针对「优秀 UI 有什么内容 / 低分 UI 缺什么」输出结构化结果，便于主 AI 汇总修复。

```
你是 UI 评测分析师。下面这张截图是 HOI4 Mod 编辑器中的某个界面（清单 ID：___）。
请先描述这个界面实际包含的所有内容区域、控件、可编辑/可展示的数据项，
然后判断它作为“词条展示与编辑工具”是否完整：

1. 可见内容：列出所有可见区块/控件/按钮/表格列/字段（尽量逐字、逐图标）
2. 词条展示：哪些游戏数据词条/字段被直接展示了？哪些只能看到摘要/计数/被隐藏？
3. 词条编辑：哪些字段能直接在界面上编辑？哪些只能通过原始文本/树节点/外部工具改？
4. 易用性：布局是否清晰、信息层级是否合理、有没有挤在一起/留白过大/按钮缺失
5. 与同类优秀 UI 对比：参照游戏内设计器或专业工具，这个界面多了什么、少了什么

最后输出 JSON 代码块：
{
  "id": "清单ID",
  "summary": "一句话总结（优秀/良好/一般/较差 + 核心原因）",
  "visible_content": ["可见内容逐项"],
  "shown_fields": ["直接展示的词条字段"],
  "missing_fields": ["应该展示或编辑但缺失的字段"],
  "raw_text_dependency": ["当前必须用原始文本/树编辑才能改的内容"],
  "strengths": ["优秀之处"],
  "weaknesses": ["缺陷与缺失"],
  "suggested_improvements": ["建议"]
}
```
